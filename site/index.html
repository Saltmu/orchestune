The Problem
課題

Delegating a big task to an AI agent is easy. Trusting the result isn't.

大きなタスクをAIエージェントに任せるのは簡単。でも、結果を信頼するのは別の話。

Once a task grows past a single prompt, dependencies, file conflicts, and progress become invisible — and by the time they surface, the rework has already cost you quota and time.

タスクが単一のプロンプトを超えて大きくなると、依存関係・ファイル競合・進捗が見えなくなります。それらが表面化する頃には、手戻りがすでにクオーターと時間を消費した後です。

Without Orchestune
Orchestuneなしだと
  • Conflicts surface only after agents have already written overlapping code
  • 競合は、エージェントが重複したコードを書き終えた後に初めて表面化する
  • Progress lives in your head — the pipeline stalls the moment you step away
  • 進捗は自分の頭の中にしかなく、席を外した瞬間にパイプラインが止まる
  • A wrongly scoped subtask means redoing the work — and burning quota twice
  • スコープを誤ったサブタスクはやり直しになり、クオーターを二重に消費する
With Orchestune
Orchestuneがあれば
  • Conflicts and unsafe parallel work are caught before any code is written
  • 競合や危険な並列実行を、コードを書く前に検出する
  • State lives in GitHub Issues and PRs — self-healing, no babysitting required
  • 状態はGitHubのIssueとPRに残り、自己修復するため見守り不要
  • A reviewable plan surfaces scope problems before agents ever start
  • レビュー可能な計画により、エージェントが着手する前にスコープの問題が見える
The Solution
解決策

Orchestune keeps every subtask, dependency, and result traceable.

Orchestuneは、すべてのサブタスク・依存関係・結果を追跡可能に保ちます。

1

Decompose large tasks into traceable work units

大きなタスクを追跡可能な作業単位へ分解

Creates a reviewable plan in which every subtask has an explicit scope, acceptance criteria, verification steps, dependencies, and expected file or symbol footprint.

各サブタスクの実装範囲、受け入れ基準、検証手順、依存関係、変更予定のファイルやシンボルを含む、レビュー可能な分解計画を作成します。

2

Validate dependencies and conflicts before implementation

実装開始前に依存関係と競合を検証

Builds a DAG from the plan and detects dependency cycles, overlapping files or symbols, shared-contract risks, and unsafe parallel work before agents modify the codebase.

計画からDAGを構築し、循環依存、ファイルやシンボルの重複、共有拡張点のリスク、危険な並列実行を、AIがコードを変更する前に検出します。

3

Provision an auditable execution plan on GitHub

実行計画をGitHub上の追跡可能なIssueへ変換

Converts the approved plan into parent and child Issues with dependency links, status labels, and implementation context, preserving why each unit of work exists.

承認された計画から、依存関係、ステータスラベル、実装に必要な文脈を持つ親Issueと子Issueを起票し、各作業の目的を記録します。

4

Coordinate autonomous implementation and integration

AIによる自律的な実装と統合を協調

Dispatches ready Issues to local or cloud coding agents, reconstructs progress from GitHub Issues and PRs, and coordinates downstream rebases and integration.

着手可能なIssueをローカルまたはクラウドのAIコーディングエージェントへ割り当て、GitHub IssueとPRから進捗を復元しながら、下流ブランチのリベースと統合を調整します。

Design Philosophy
設計思想

Quota efficiency, not wall-clock speed

実時間の速さではなく、クオーター効率

Orchestune is for individual developers and small teams working with AI coding agents. The scarce resource here is not wall-clock time — it is your AI usage quota (a subscription's session/weekly allowance) and the hours a human can actually be at the desk.

Orchestuneは、AIコーディングエージェントを使う個人開発者と少人数チームのためのものです。ここでの希少資源は実時間ではなく、AI利用クオーター（サブスクリプションのセッション/週次の使用枠）と、人間が席にいられる時間です。

  • Rework is the main waste. Conflict-prevention analysis and the shared-contract gate trade a small up-front planning cost for avoided rework.
  • 手戻りが最大の無駄。 競合防止の分析と共有拡張点のゲートは、わずかな事前計画コストと引き換えに手戻りを回避します。
  • Parallelism is the mechanism, not the goal. Independent subtasks let several agents burn quota at once instead of one agent burning it in sequence.
  • 並列性は目的ではなく手段。 独立したサブタスクにより、複数のエージェントが同時にクオーターを消費できます（1つのエージェントが順番に消費するのではなく）。
  • Unattended operation converts parallelism into quota efficiency. State is self-healing from GitHub, and human judgment is confined to two approval gates.
  • 無人での実行が、並列性をクオーター効率へ変換する。 状態はGitHubから自己修復し、人間の判断は2つの承認ゲートに限定されます。
How It Works
仕組み

From a big idea to merged, traceable work

大きなアイデアから、統合され追跡可能な成果物へ

01

Decompose & validate

分解と検証

Your agent turns the task into a reviewable decomposition plan, then validates its dependency DAG and conflict risks. You review and approve.

エージェントがタスクをレビュー可能な分解計画に変換し、依存DAGと競合リスクを検証します。あなたはその計画をレビューして承認します。

02

Provision

Issue起票

Once approved, your agent creates dependency-linked parent and child GitHub Issues from the plan.

承認後、エージェントが依存関係で結ばれたGitHubの親Issueと子Issueを作成します。

03

Dispatch

ディスパッチ

Your agent starts eligible subtasks in isolated worktrees using local or cloud coding agents.

着手可能なサブタスクを、分離されたworktreeでローカルまたはクラウドのAIコーディングエージェントへ割り当てます。

04

Trace & integrate

追跡と統合

Each subtask is tracked through its Issue, branch, PR, and CI result while Orchestune coordinates dependent work and integration.

各サブタスクのIssue、ブランチ、PR、CI結果を追跡しながら、Orchestuneが依存タスクと統合を調整します。
